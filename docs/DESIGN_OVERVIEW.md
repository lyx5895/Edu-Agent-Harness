# OmniEdu 教学 Harness：设计思路

本文讲五件事：

1. 为什么需要 harness；
2. harness 怎么设计，为什么这么设计（学生侧和教师侧两条流程）；
3. 用一道题把两条流程串起来；
4. 外面的教学系统怎么设计；
5. 这套设计怎么辅助教学，以及现状和下一步。

技术实现见 [ARCHITECTURE.md](ARCHITECTURE.md)，验收数据见 [FEATURES_AND_TESTS.md](FEATURES_AND_TESTS.md)。

## 一、为什么需要 harness

大模型很会"说"：能理解各种表述的作答，能用自然语言讲解，几乎不需要人工编写辅导内容。但直接让它辅导学生，有四类风险：

| 风险 | 表现 |
|---|---|
| **代替学生思考** | 学生要提示，模型直接给出解法 |
| **误判** | 答错说对，答对说错 |
| **虚假的"学会了"** | 在提示帮助下做对，被当成已经掌握 |
| **不可追溯** | 出了错，说不清是哪一步、根据什么 |

第一类风险的代价已经有实证：高中数学的随机对照试验中，学生使用不加约束的 GPT-4，练习成绩大幅提高，但撤掉以后考试成绩比没用过的学生**低 17%**；加了教学约束的版本基本消除了这种损害（Bastani 等，PNAS 2025）。

**harness 就是包在模型外面的那层约束。** 这个词原义是马具，套在马身上，让马的力气用在该用的方向上。这里的"马"就是模型。

我们的总原则是：

> **模型负责理解和表达，判断由规则和可核对的证据来做。**

## 二、整体结构：三方、两层

```
          ┌──────────────────────── 教学系统 ────────────────────────┐
          │                                                          │
  学生 ───┤  学生工作台：做题、要提示、做检查                          │
          │        │                                                 │
  老师 ───┤  教师工作台：备课出题、布置、看学情、复核改判              │
          │        │                         │                       │
          │  ┌─────▼────── Harness ──────────▼───────────────────┐   │
          │  │  学生侧：辅导流程          教师侧：备课与教学管理   │   │
          │  │  策略·判定·审核·记录       起草·核对·定稿·学情汇总   │   │
          │  │            └──── 共用证据与判定工具 ────┘            │   │
          │  │                     ▲                              │   │
          │  │              大模型（被约束的对象）                  │   │
          │  └────────────────────────────────────────────────────┘   │
          └──────────────────────────────────────────────────────────┘
```

三方各自的角色：

- **模型**是被约束的对象：它为学生写的每句话、为老师起草的每道题，都要经过 harness；
- **学生**是辅导的对象：模型的辅导直接送到学生面前，中间没有人，所以 harness 要自己当关卡；
- **老师**是教学的主导者：模型为老师起草题目、推荐知识点，老师定稿；老师设定教法和要求，处理系统上报的例外，复核和纠正判定。

harness 因此有两条流程：学生侧的辅导流程，教师侧的备课与教学管理流程（第三节分别介绍）。两条流程共用同一套证据和判定工具：老师定下的标准用来判学生，学生的证据又汇总给老师。

两层的分工也很清楚：harness 保证模型的输出可靠，教学系统负责让老师和学生用起来。两层之间的接口很窄，换掉界面不影响 harness，换掉模型或教学策略也不影响界面。

## 三、Harness 怎么设计，为什么这么设计

模型在系统里服务两类人，所以 harness 也围绕两条流程设计：

| | 学生侧：辅导流程 | 教师侧：备课与教学管理 |
|---|---|---|
| 模型做什么 | 判定作答、写提示和讲解 | 起草题目、评分要求、参考答案，推荐知识点 |
| 输出给谁 | 直接给学生，**中间没有人** | 先给老师，**老师定稿后才生效** |
| harness 的角色 | **自己当关卡**：每句话送出前都要拦一遍 | **给老师当助手**：让草稿有据可查、把问题提前暴露、把老师的决定变成硬约束 |
| 最怕的错误 | 泄露答案、误判、虚假的"学会了" | 参考答案错误（会让全班的判定都跟着错）、凭空编造、结论无法核对 |

两条流程共用同一套证据和判定工具：老师发布的题目和评分要求，就是辅导时判定的标准；辅导中产生的证据，又汇总成老师看到的学情。

### （一）学生侧：辅导流程的 harness

学生每次操作（交作答、要提示、要讲解、做检查），harness 都按同样的步骤处理一次：

```
① 收集上下文 → ② 判定作答 → ③ 选择教学动作 → ④ 模型写回复 → ⑤ 审核回复 → ⑥ 记录
```

其中只有 ② 和 ④ 用到模型，并且两步的输出都要经过核对；③ 完全由规则决定。

#### 设计 1：教法由规则决定，不由模型决定

**做法**：下一步怎么教（追问、指出错误位置、给哪一级提示、讲解、转老师）由一组固定规则决定。模型只负责把这个动作写成自然的话。

提示分三级，逐级给出更多帮助：

1. 点明关键概念；
2. 说明下一步做什么；
3. 给一道只差关键一步的类似例题。

学生连续几轮没有进展，自动升到下一级；三级都用完，转给老师。

**为什么**：
- 模型自己决定教法，很容易一步到位，直接讲出答案；
- 规则可以由教育研究和老师来设计、讨论、修改；
- 同样的情况一定得到同样的决策，事后可以回放核对。

#### 设计 2：每个判定都要有学生原文作依据

**做法**：模型判定"对"或"错"时，必须指出依据的是学生的哪一句话，程序核对这句话确实出现在学生的作答里。核对不上，这次判定就不算数，转给老师。能用工具判的（比如代数计算）以工具为准；配置了第二个模型时，两个模型意见相反也转给老师。

**为什么**：
- 模型可能"编"出学生没说过的话来支持它的判断；要求逐字引用原文，是最简单有效的防线；
- 老师复核时，看原文这一句就能判断，不用重读整份作答；
- 拿不准的交给人，而不是让模型硬判。

#### 设计 3：每条回复先审核，再给学生

**做法**：模型写好的回复先过两道检查。

- **程序检查**：不能出现答案和最终数值，不能用题目里的数字替学生列式，不能说"你已经掌握了"。
- **模型审核**：由另一个模型按同一份标准审核。

不通过就带着理由重写一次；还不通过，就用按级别预先写好的模板。学生收到的是模型写的还是模板，界面上如实标出。

**为什么**：
- 直接给答案是最大的教学风险，必须在送到学生面前之前拦下；
- 准备了兜底模板，提示阶梯就不会因为模型写坏了而中断；
- 如实标注，老师和研究者才能知道模型实际表现如何，而不是被兜底掩盖。

#### 设计 4：区分"做对了"和"学会了"

**做法**：系统把每次做对分成几类：

- 没用帮助的**练习完成**；
- 在提示或讲解帮助下的**辅助完成**；
- **独立检查**中做对。

只有最后一种才算学会。独立检查必须用学生**没见过的新题**，检查时不提供任何提示，也不参考之前的对话。

**为什么**：
- 在提示下做对，不代表能独立做对，这正是开头那项研究里"练习成绩高、考试成绩低"的原因；
- 只有分清这几种情况，老师看到的"已完成"才有意义。

#### 设计 5：学习记录由证据推导，模型不能直接写

**做法**：每个学生在每个知识点上的状态（需要帮助、辅助完成、已独立完成、需要重新检查……）全部由上面那些有原文依据的证据推导出来。模型不能写"该生已掌握"，系统里也没有模型估出来的掌握度分数。

**为什么**：
- 模型给出的掌握度是印象分，没法核对，也没法纠正；
- 由证据推导的状态，每一个都能追溯到具体某次作答的原文。

#### 设计 6：全程留痕，可以回放，可以纠正

**做法**：每一轮都记录完整轨迹，包括规则的输入、做出的决策、模型说了什么、审核结果、状态怎么变化。老师可以：

- **回放**：用同一套规则重算所有决策，核对是否一致；
- **改判**：改判以后，所有用到这条证据的后续记录自动标为"需要重新检查"。

**为什么**：
- AI 一定会出错，关键是出错后能找到原因、修正影响；
- 改一处就能修正所有受影响的记录，老师才敢放心使用；
- 轨迹本身也是改进模型的数据，比如"被否决的回复和通过的重写"可以用来训练模型。

### （二）教师侧：备课与教学管理的 harness

老师从备课到看学情，经过的流程如下：

```
老师提供：教材、学习目标、题目
   │
   ▼
① 处理材料      提取 PDF 和文本，按段落和页码切分，检索与目标相关的段落
   │
   ▼
② 模型起草      题目、评分要求、参考答案、知识点（结构化输出）
   │
   ▼
③ 程序核对      引用的原文是否存在？知识点是否在知识库里？参考答案能否通过工具检查？
   │
   ▼
④ 老师定稿      逐题修改，明确确认审核，否则不能发布
   │
   ▼
⑤ 发布          把判定工具绑定到题目上，老师的设定转成硬约束
   │
   ═══════════  学生做题（学生侧流程）  ═══════════
   │
   ▼
⑥ 学情汇总      由规则从证据中得出，不用模型 → 例外上报老师 → 老师改判，自动传播
```

这条流程里，模型只出现在第 ② 步，其余都是程序和老师。下面是六条设计。

#### 设计 7：模型只起草，老师定稿

**做法**：模型生成的题目和参考答案，一律存成可编辑的草稿，标记为"模型生成、未审核"。老师必须明确勾选"已审核题目、参考答案和评分要求"，并写一句审核说明，才能发布；未审核的模型草稿，从任何入口都发布不了。发布以后，来源标记会一直跟着这道题：

- 老师写的；
- 模型写、老师审核过的；
- 模型写、只经过模型审核的。

来源较弱的题，后续的判定在复核队列里会标出风险。

**为什么**：
- 学生侧没有人把关，所以 harness 要自己当关卡；教师侧有老师，最终决定权应该留给老师；
- 参考答案是判对错的标准，影响比一条回复大得多，值得老师花时间看；
- 标明来源，老师和研究者才知道哪些结论建立在未经核实的内容上。

#### 设计 8：模型的草稿必须有据可查，不能凭空编造

**做法**：
- **引用教材要能核对**：模型出题时如果引用教材原文，程序核对这段话确实在老师上传的材料里，核对不上就不生成。题目会记下出自教材的第几页，老师可以回去对照；
- **知识点只能从知识库里选**：推荐知识点时，程序先从知识库检索出几十个候选，模型**只能在候选的编号里选**，不能自己编名字。模型不可用时，退回按关键词检索。老师保存的知识点编号，发布时还会再核对一次是否存在；
- **材料只当数据**：提示词明确规定，材料里出现的"指令"一律不执行，防止教材或上传文件里夹带的文字改变出题行为。

**为什么**：
- 模型最常见的问题是"说得像真的"：编出教材里没有的引文，编出不存在的知识点；
- 把模型的选择限制在可核对的范围内，比事后检查它有没有编造更可靠，这和学生侧"判定必须引用学生原文"是同一个思路。

#### 设计 9：发布即绑定判定工具，参考答案先自检

**做法**：老师发布题目时，harness 把这道题变成"能自动判定"的任务，并先检查参考答案本身：

- 题目里有方程或代数式时，自动绑定代数验证器。验证器用的式子必须**逐字来自题目**，然后用它检查参考答案，对不上就不能发布；
- 老师写的每个可以用工具判的分项（数值、单位、因式分解、原文引用、字数），都先用参考答案试判一遍，参考答案自己通不过就不能发布；
- 发布前，老师可以随时预览"这道题能否自动判定、参考答案能否通过"。

这些检查对**老师自己写的参考答案同样适用**。

**为什么**：
- 判定的可靠性不只取决于模型，也取决于标准本身对不对。老师的笔误、模型的算错，都应该在学生做题之前拦下；
- 能用工具判的部分在发布时就固定下来，之后判这道题以工具为准，减少对模型判定的依赖。

#### 设计 10：老师的设置是硬约束，不是给模型的建议

**做法**：老师发布题目时的设定，harness 把它们变成规则和程序检查，而不是只写进提示词：

| 老师的设定 | 在辅导中如何生效 |
|---|---|
| 关闭完整讲解 | 学生请求讲解会被直接拒绝，只能要提示 |
| 教学批注（如"先让学生画线段图"） | 每轮辅导都交给模型作为依据 |
| 分项评分要求（如列式、计算、单位） | 判定逐项进行；能用工具判的项由程序判 |
| 检查要求 | 独立检查题必须覆盖这些要求，否则打回重出 |
| 指定检查题 | 独立检查优先从老师给的题中选；用完就请老师补充，不用模型题凑数 |
| 学习路径（先修关系） | 先修知识点没有独立完成，就不推荐后面的知识点 |

**为什么**：
- 写进提示词的要求，模型可能做不到。老师说"不要讲答案"，就必须一定做到，否则老师不会信任系统；
- 教法的主导权留在老师手里，系统执行老师的教学意图，而不是替老师决定怎么教。

#### 设计 11：给老师看的学情由规则得出，不由模型总结

**做法**：老师看板上的所有结论都不调用模型，全部由规则从有原文依据的证据中算出：

- 每个学生在每个知识点上的状态；
- 遇到同类困难的学生分组（例如"这五个人都在单位这一项出错"），依据是逐项评分的结果；
- 每个知识点的下一步建议（补先修、换讲法、安排迁移检查或复习）；
- 补救练习的完成情况（必须通过独立检查才算完成）。

**为什么**：
- 模型写的"班级学情总结"读起来流畅，但无法核对，老师据此做教学决策有风险；
- 由规则得出的结论，每一条都能点开查看学生原文；老师不同意，改判就能修正，不需要和模型"争论"；
- 补救练习只认独立检查，老师看到的完成率才不会虚高。

#### 设计 12：只把例外交给老师，改一处就能修正全部

**做法**：
- **按风险上报**：三类情况进入老师的复核队列，每条都附上风险原因和学生原文：
  - 判定拿不准：模型引用不了原文、模型自己没把握、两个模型意见相反；
  - 辅导走不下去：三级提示用完学生仍没进展，或模型连续写不出合格的回复；
  - 结论依据较弱：独立检查只由模型判定，或者参考答案是模型写的。
- **改判自动传播**：老师改判一条证据后，所有用到它的后续记录自动标为"需要重新检查"，学情和学习路径随之重算。

**为什么**：
- 老师没有时间看每一段对话。事事上报等于没有帮老师省事，什么都不报老师又不敢放手；
- 按风险上报，老师的精力只花在真正需要人判断的地方；
- 改一处就能修正所有受影响的结论，老师不用自己去找一个错误影响了哪些地方。

#### 教师侧目前的不足

教师侧的 harness 比学生侧薄。学生侧"下一步怎么教"由规则决定；教师侧"出什么题、出多难"还完全由模型决定，harness 只做事后核对。另外，工具判不了的参考答案（说明题、阅读题等）目前只能靠老师审核。改进方向见第七节。

### 小结：harness 补回了智能辅导系统的结构

传统的智能辅导系统由四个核心部分组成，另外还要靠一套内容编写工具，由老师或专家把题目和标准录进系统。大模型几乎省掉了人工编写辅导内容的工作，但也把这些结构一起"跳过"了。harness 把它们补了回来：学生侧主要补前三部分，教师侧补内容编写这一环。

| 智能辅导系统的组成部分 | 回答的问题 | 本项目中由什么负责 |
|---|---|---|
| 领域模型 | 什么是对的 | 参考答案、评分要求、代数工具、原文核对 |
| 教学模型 | 下一步怎么教 | 规则化的教学策略、三级提示 |
| 学生模型 | 学生现在会什么 | 证据分类和学习记录（目前最弱，见第七节） |
| 交互界面 | 怎么交流 | 大模型的理解和表达，加上工作台 |
| 内容编写工具 | 题目和标准从哪里来 | 模型起草，程序核对，老师定稿（设计 7–9） |

## 四、用一道题串起来

下面用"平均速度"这道题，走一遍两条流程。括号里是用到的设计。系统自带的预览班级就是这道题，讲的时候可以对照演示。

**① 备课（教师侧）**

- 老师上传第三章教材，写下学习目标"能根据路程和时间求平均速度，并写出计算过程和单位"；
- 模型起草题目："小明骑车 3 小时行了 45 千米，他的平均速度是多少？"同时起草评分要求和参考答案"45 ÷ 3 = 15 千米/小时"。草稿引用的教材原文经过核对，并标出出自第几页；推荐的知识点"平均速度"是从知识库里选的（设计 8）；
- 老师把评分要求拆成"列式、计算、单位"三项，加一条批注"先让学生说出速度的含义"。系统用参考答案逐项试判，三项都通过（设计 9、10）；
- 老师勾选"已审核"后发布到班级（设计 7）。

**② 学生做题（学生侧）**

- **陈一鸣**写"45 × 3 = 135"。判定为错误，依据就是他的原话"45 × 3 = 135"（设计 2）。规则选择"指出错误位置并追问"，模型写道："你算的是 45 乘 3，平均速度表示每小时走多少千米，把 45 千米平均分到 3 个小时里，每小时走的会比 45 千米多还是少？"这条回复审核通过后发出（设计 1、3）；
- **王可**写"45 + 3 = 48"，然后连续要了两次提示。第一次给概念级提示，提醒速度是什么意思；第二次给步骤级提示。模型起草的第二级提示里写了"45 ÷ 3"，等于替学生列了式，被程序检查拦下，换成合格的版本（设计 1、3）。王可随后改对，但记为"**辅助完成**"，不算学会（设计 4）；
- **林小雨**一次做对，记为"练习完成"。她接着开始独立检查，系统换了一道新题："一辆电动车 4 小时行驶了 60 千米……"。检查时界面上没有提示按钮，她独立做对，才记为"**已独立完成**"（设计 4、5）。

**③ 老师看学情（教师侧）**

- 看板显示：林小雨已独立完成，王可辅助完成；陈一鸣和赵子涵需要帮助，两人都在"列式"这一项出错，被归为一组。这些都由规则从证据中算出，点开每一条都能看到学生原话（设计 11）；
- 老师给这一组布置补救练习，截止时间是后天。补救练习必须通过独立检查才算完成（设计 10、11）；
- 复核队列里有一条：赵子涵写"3 ÷ 45 ≈ 0.07"，判为错误，但没有第二个模型附议（设计 12）。

**④ 纠正（教师侧）**

- 老师复核时如果发现某次判定错了，改判之后，所有用到这条证据的记录都自动标为"需要重新检查"，看板随之更新（设计 6、12）；
- 回放可以证明当时每一步选哪种教学动作，都是规则算出来的（设计 6）。

**这道题里，模型做了什么**：起草题目、判断学生写的是什么意思、把教学动作写成自然的话。**模型没有决定的事**：教什么、怎么教、学生算不算学会、老师看到什么。这就是开头那条原则："模型负责理解和表达，判断由规则和可核对的证据来做。"

## 五、外面的教学系统怎么设计

harness 管"模型可靠"，教学系统管"有人用、用得顺"。设计上的几个选择：

### 学生工作台：一个对话区，配几个按钮

- 左边是要做的题（老师布置的、补救练习、自己提的问题），右边是和辅导老师的对话；
- 按钮和教学动作一一对应：提交作答、要提示、要讲解、回答追问、开始独立检查；
- 每条回复带标签，比如"第二级提示"，学生知道自己用了多少帮助；
- 进入独立检查后，提示和讲解按钮直接消失。约束不只写在规则里，**界面上也做不到违规**。

### 教师工作台：围绕"例外"组织

| 页面 | 作用 |
|---|---|
| 看板 | 全班学习状态、需要复核的判定、遇到同类困难的学生分组 |
| 发布 | 出题、写评分要求，发布前先预览能否自动判定 |
| 练习包 | 从教材或要求批量出题，老师改完再发布 |
| 学习路径 | 按先修关系安排知识点顺序 |
| 复核 | 看学生原文、判定依据和过程记录，确认或改判 |

**为什么围绕例外**：老师没有时间看每一段对话，所以页面的入口是看板和复核队列，而不是聊天记录（对应设计 12）。

### 后端：简单、安全、可部署

- **两种运行模式**：本地演示不需要登录；课堂模式下每人一个账号，学生只能看自己的，老师只能看本班的。每个接口都必须声明权限，漏掉一个，自动测试就会失败；
- **同时使用不冲突**：一个学生等模型回复时，不会挡住其他学生；网络重试或重复点击不会产生重复记录；
- **部署简单**：一个服务进程加一个数据库文件，界面不需要单独构建。

## 六、这套设计怎么辅助教学

把老师的教学环节和上面的设计对应起来：

| 教学环节 | 系统帮老师做什么 | 靠哪些设计 |
|---|---|---|
| **备课** | 从教材批量起草题目、评分要求和参考答案；发布前检查参考答案，并确认能自动判定 | 7、8、9 |
| **辅导**（最主要的帮助） | 按老师认可的教法，一对一辅导全班每个学生：先问依据、再指出错误、逐级提示、最后讲解；老师的批注和"关闭讲解"一定生效 | 1、3、10 |
| **诊断** | 区分谁独立学会了、谁在帮助下做对了；把同类错误的学生自动分组；每个结论都能看到学生原话 | 2、4、5、11 |
| **补救与复习** | 给出下一步建议；补救练习必须通过独立检查才算完成；按间隔安排复习 | 4、10、11 |
| **质量把关** | 只把有风险的判定交给老师；改判一处，受影响的结论全部重算；能向学生和家长出示依据 | 6、12 |

其中**辅导**是最主要的帮助。老师没法同时一对一辅导四十个学生，这个系统相当于给了老师一个**按自己方法教的分身**，课后的个别辅导可以放心交给它。

### 对学生的帮助

- 得到的是引导，而不是答案，这避免了开头研究里"用 AI 时成绩高，撤掉后成绩低"的问题；
- 随时有人回应，帮助逐级增加，不会一上来就被讲完；
- 独立检查用新题，学生自己也知道是不是真的会了。

### 一句话总结

> 这个 harness 让老师可以**把日常辅导放心交给 AI**：教法由老师掌控，判定有原文依据，学会与否有独立检查作证，出了错能追溯、能纠正。老师的时间从盯防和核查，转到处理真正需要人的例外和集中讲解。

## 七、现状与局限

**已经做到的（v0.10 验收）**：
- 提示与讲解评测（真实模型，数学、物理、科学共 4 道题，每道 4 次）：三级提示阶梯 16/16 完整走完，零答案泄露；完整讲解 16/16 送达，数值题 12/12 得出最终答案；
- 真实浏览器端到端检查 16/16 通过；
- 自动化测试 174 项全部通过。

**还不足的**：

| 方面 | 说明 |
|---|---|
| 缺少真实课堂数据 | 没有在真实师生中测量学习效果和老师节省的时间。这是下一步最重要的工作 |
| 教师侧没有验收数据 | 上面的验收数据都来自学生侧（辅导和判定）；教师侧还没有测过，例如批量出题时参考答案的错误率、老师审核时要修改的比例 |
| 学生模型偏弱 | 只有证据分类，没有掌握程度的估计和预测 |
| 出题没有规则层 | 辅导时"怎么教"由规则决定，出题时"出什么题、多难"完全由模型决定，harness 只做事后核对。批量出题时，工具判不了的参考答案（说明题、阅读题等）只能靠老师审核 |
| 小模型的局限 | 只用 9B 模型时，部分提示仍会说得太多，建议配合第二个模型做审核 |
| 帮助效果未分析 | 已经记录了"给了什么帮助、之后表现如何"，但还没分析哪种帮助更有效 |

**下一步方向**：

**（一）出题：从"模型生成、事后核对"变成"规则决定、程序核算"**

辅导部分遵循"规则决定、模型表达"，出题部分还没有做到。下面按投入从小到大排列：

1. **批量出的题也做参考答案自测**：把模型写的参考答案当作学生作答，判一遍。判不出"正确"，说明题目、评分要求和参考答案之间有矛盾，在草稿里标出来提醒老师重点审核。独立检查题已经这样做了，练习包还没有。
2. **出题改由第二个模型审核**：现在独立检查题由出题的模型自己审核。辅导回复已经改为由复核模型把关，出题也应该这样做。
3. **能算的题，答案由程序算**：出题时，模型除了题目，还要交一份程序能执行的解法（算式、方程或一小段代码）。程序检查解法里用到的量题目里都有，再执行解法得出参考答案。分工如下：
   - 题目的情境和问法仍由模型每次重新写，所以题目不会被穷尽；
   - 参考答案由程序算出，不会出现模型心算错误、改了数字没改答案、题目缺条件这类问题。

   这和"判定要有原文依据"是同一个思路：模型的结论都要有可核对的依据。说明题、阅读题这类算不出来的题，仍用第 1、2 条把关。
4. **针对学生的错误出补救题**：系统已经记录了每个学生的错误原因和同类困难分组，比如"五个人都把路程和时间相乘"。补救题应该专门针对这个错误出，而不是泛泛地再出一道同类题。
5. **利用知识点关系和难度**：学生卡住时，出先修知识点的题；同一目标下，由易到难安排。知识点库目前只用来推荐知识点标签，还没有用在出题上。
6. **按意思去重**：现在只有文字完全相同才算重复题，换了说法、数字没变的题能通过去重。

**（二）学情：从"记录证据"到"分析证据"**

7. **补充学生模型**：在证据分类的基础上，估计掌握程度和遗忘情况，复习时间按学生的实际表现调整，而不是固定间隔。
8. **分析帮助效果**：系统已经记录了"给了哪种帮助、之后表现如何"。下一步要统计哪种帮助对哪类错误更有效，反过来用来调整教学策略。

**（三）模型：用交互数据改进模型本身**

9. **把轨迹变成训练数据**：例如，用"被审核否决的回复"和"通过审核的重写"组成偏好数据，训练模型一开始就写出合格的提示，减少对审核和兜底模板的依赖。

**（四）验证：真实课堂试用**

10. **小规模真实课堂试用**：同时检验两件事，一是 harness 在真实学生面前是否可靠，二是系统对老师和学生是否真的有用。需要测量的包括学习效果（前测与后测、迁移、保持）、老师节省的时间，以及复核队列的误报率。这是上面所有改进中最重要的一项。
