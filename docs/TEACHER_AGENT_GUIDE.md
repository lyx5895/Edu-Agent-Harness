# 教师端 Edu-Agent：使用说明与验收记录

本文对应 `teacher-agent` 分支的第一版实现，设计见 [TEACHER_AGENT_DESIGN.md](TEACHER_AGENT_DESIGN.md)。学生端（`harness/`）冻结在标签 `v0.10-student`，这一版没有改动它。

## 启动

```bash
cd /default-filesys/workspace/ysb/Edu
export EDU_LLM_API_KEY=...            # 模型网关密钥，只放在环境变量里
.envs/harness/bin/python -m uvicorn edu_app.api:app --host 127.0.0.1 --port 7870
```

在自己电脑上转发端口后打开 http://127.0.0.1:7870 （接口文档在 `/docs`）：

```bash
ssh -N -L 7870:127.0.0.1:7870 <服务器>
```

- 没有设置密钥也能启动，但只能查看已有数据，所有需要模型的按钮会提示“未配置模型”。
- 数据存在 `data/edu.sqlite`（`EDU_DB` 可改）。目前是单人本地工具，没有账号，只应监听 127.0.0.1。

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `EDU_LLM_API_KEY` | 无 | 网关密钥 |
| `EDU_LLM_BASE_URL` | `https://lightingtheword.com/v1` | 网关地址 |
| `EDU_MODEL_GENERATOR` / `GRADER` / `ANALYST` | `DeepSeek-V4.1-Flash` | 出题、批改、学情分析 |
| `EDU_MODEL_REVIEWER` | `qwen3.8-flash` | 失分判定的盲审复核、出题自检的独立解题、抽检 |
| `EDU_AUDIT_RATE` | `0.05` | 判满分的作答被随机抽检的比例 |
| `EDU_AB_RATE` | `0.2` | 不勾选时，出题自动出 A/B 两版的比例 |
| `EDU_DB` | `data/edu.sqlite` | 数据库 |

## 一次完整的使用流程

页面上方是项目概况：各类产物已确认的数量、待复核数，以及“下一步”按钮（点击会跳到要操作的位置）。下面五个标签页严格对应教学闭环的五步，“记录与导出”单独放在右侧，不编号。

```
01 备课设计 ──按目标出题──▶ 02 出题改题 ──依据标准批改──▶ 03 作业批改
     ▲                         ▲                                │
优化后续备课               讲评后再练（新一轮）              汇总批改结果
     │                         │                                ▼
05 讲题答疑 ◀──────定位讲解重点────────────────────── 04 学情分析
```

每个阶段顶部的“下一步”只在 01–05 之间跳转：本阶段没完成时按钮是灰的，下面写明还差什么。页面内部的操作（生成、保存、确认）在各自的卡片里。

1. **新建项目**：项目名称、学科（10 个科目，名称里含学科名时自动选上）、年级、说明。还没有题目时，可以在“编辑项目”里改学科。
2. **01 备课设计**：
   - 先填写**课时信息**：知识模块、课时、**本课时内容**（目标和活动只围绕这部分）、学生基础、其他要求；
   - **对应课程标准**（10 个学科，来自教育部《普通高中课程标准（2017年版2020年修订）》必修和选择性必修；语文为 18 个学习任务群；人工智能对应《信息技术》课标，其中“人工智能初步”是选择性必修模块）：按课时信息自动匹配课标“内容要求”条目，只显示勾选的条目，其他候选折叠；可以搜索、增减，或选“不参考课标”。标“选学”的条目（不作为考试要求）不会被自动勾选；匹配把握不大时（例如课标里没有这个词，或内容超出课标）不自动勾选，提示老师自己选；
   - 生成时，每条目标必须标出依据的课标条目；要求不能高于课标用词（课标写“了解”，目标不能写“理解”“掌握”）；同时遵守该主题的学业要求和教学提示。服务器核对引用的编号，编造的编号会被去掉；没有依据的目标标“未对应课标”，要求高于课标用词的标“要求高于课标”，老师修改目标后重新检查；
   - **参考材料**可选，可以粘贴或上传 .txt / .md / 文字版 PDF，有材料时内容范围更准；
   - 点“生成备课方案”，一次生成一份完整方案：教学目标（含达成标准）、重点、难点、课堂活动（用时与对应目标）；
   - 在同一个地方修改，然后**整体确认**；
   - 确认后，目标、重点难点会一起带入出题和讲评。修改已确认的方案时选“实质修改”，基于旧方案出的题会被标记“依据已变化”。
3. **02 出题改题**：
   - 选题型、数量、难度 →“生成题目”。每道题会由另一个模型在不看答案的情况下独立解一遍，与参考答案不一致的标为“答案存疑”；
   - 勾选“出 A/B 两版”时，先在两版中选一版；
   - 编辑题目或评分标准会生成新版本，点“确认题目与评分标准”后生效；修改已确认的内容时，要选择“实质修改”或“文字修改”；
   - 也可以“导入现成试卷”或“手工添加题目”；
   - “讲评后再练”生成的题目也在这里，选择对应轮次确认。
4. **03 作业批改**：
   - 先加学生名单（只写代号）；
   - 再粘贴 CSV 导入作答，每行是 `学生代号,题号,作答`；名单外的学生会被列出来，不会自动导入；
   - 点“批改本轮作答”；
   - 复核队列里逐个要点给分，然后“提交老师判定”；
   - 其余的“批量确认”。
5. **04 学情分析**：
   - “汇总学情”给出各题、各要点的得分率，失分标签统计，以及引用学生原文的问题模式；证据不足时给出补查问题。确认问题模式；
   - 还没有作答时，只能输出“可能的易错点”；
   - 第二轮批改确认后，在这里“对比”两轮。
6. **05 讲题答疑**：
   - 勾选问题模式 →“定位讲解重点，生成讲评稿”：讲解重点、每类问题的关键步骤、典型错误辨析和课堂追问。典型错误必须是学生原文，服务器核对，编造的会被去掉；
   - 编辑后确认；
   - “生成再练题”：针对这些问题出一轮新题（会参考已确认讲评稿的重点），回到 02 确认，再到 03 导入新一轮作答；
   - “进入下一课时 · 优化后续备课”：新建下一课时的项目，沿用学科、年级、学生基础和学生名单，课时自动加一（可改）。本课时已确认的问题模式（含再练结果）、学情概述、讲评重点和本课目标会冻结成一份快照带过去，显示在下一课时备课页顶部；生成备课方案时模型会据此安排简短的回顾或巩固，并在备注里写明对应关系。已建过下一课时的，按钮直接跳过去。
7. **记录与导出**：
   - 上游有实质修改后，引用旧版本的产物列在这里，可以“保留原结果”或“重新批改”；
   - “导出 JSON”下载研究记录。

## 与设计的差异

1. **过期传递在老师确认的内容处停止。** 设计里写的是沿引用关系一直传递。实际跑下来，修改第 1 轮的评分标准会经过“问题模式 → 巩固题”一路传到第 2 轮的批改，噪声很大。现在的规则是：
   - 题目、评分标准、目标这类老师确认的内容会被标记“依据已变化”，但不再往下传；
   - 学生作答永远不标记；
   - 批改、学情、问题模式、对比这类计算结果继续往下传。
2. **出题自检对选择、判断、填空题比对“最终答案”。** 解题模型额外输出 `final_answer`；选项会带字母发给它。否则模型用选项内容作答，会被误判为不一致。
3. **选择题作答写的是选项内容时，按内容对回字母。** 学生有时会抄选项原文。

## 验收记录（2026-11-18）

**自动化测试**：`.envs/harness/bin/python -m pytest -q tests` 共 201 个，全部通过。其中教师端 27 个（`tests/test_edu_*.py`，使用脚本化的假模型），原有学生端 174 个不受影响。

**批改准确性**：中文数学判定集全量 392 份（`scripts/edu_eval_grading.py`，结果在 `reports/edu/grading-stepverify-zh.json`）。DeepSeek-V4.1-Flash 主判，qwen3.8-flash 复核：

| 指标 | 结果 |
|---|---|
| 错误解答被判为正确 | 3.1%（6/196） |
| 正确解答被判为错误 | 0.5%（1/196） |
| 转老师 | 5.1% |
| 调用失败 | 0 |
| 每份作答平均 token | 约 2100 |

“错判为对”的 6 份中，有一部分是数据集本身的标注问题（见设计文档 8.2 节）。这个数据集是翻译过来的小学应用题，不能代表高中各科。

**真实模型走通全流程**（`scripts/edu_smoke.py`，数学“对数不等式”）：

- 起草目标 → 出题（含 4 道生成题的独立解题自检）→ 6 名学生作答 → 批改与复核 → 学情分析 → 巩固练习，都正常完成。
- 一整轮约 2 分钟，约 4 万 token。
- 例子：
  - 只写了 `x<7` 的学生，定义域和取交集两个要点被判失分，标签是“条件遗漏”，复核模型同意；
  - 把 `log_2(x-3)<2` 错写成 `x-3<2` 的学生，后续步骤是否连带扣分两个模型意见不一，转给了老师。

**多学科抽查**：历史（材料分析、单选）、英语（语言题、填空）、人工智能（简答、单选）各出一组题。

- 用参考答案作答都得满分，敷衍作答都是 0 分并打上标签；
- 修复上面差异第 2 条之后，选择题的自检全部一致。

**浏览器**：用无头 Chromium 走完整条流程，包括 A/B 选择、复核队列改判、实质修改后过期提示和重新批改、导出下载。没有页面脚本错误；桌面和手机宽度都没有横向溢出。

## 已知限制

- 评测数据仍然只有数学（小学难度）和 5 科的模型生成题。思想政治、历史、地理、人工智能还没有评测集，写作题也没有。
- 模型调用是同步的：出题加自检约 1 分钟，批改一个班取决于人数（默认 8 路并发）。页面在等待时只显示按钮上的“…中”提示。
- 没有账号体系，只适合单人本地使用。
- 网关上同一个模型名可能对应不同后端（DeepSeek 返回两个版本标识），每次调用都记录了实际返回的版本。
