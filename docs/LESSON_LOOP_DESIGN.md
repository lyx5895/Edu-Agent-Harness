# 首版收束：一节课的教学闭环

状态：待评审  
日期：2026-11-21  
关系：收窄 [课程教学工作台设计草案](COURSE_WORKSPACE_DESIGN.md) 的首版范围；回到 [原始需求](design.md)（`harness 设计.pdf`）的“一节课一个项目”，只吸收其中“背景只填一次”这一点

## 1 为什么收束

原始需求要的是：围绕**一节课**，把备课、出题改题、作业批改、学情分析、讲题答疑串成闭环，前面确认的东西后面接着用。

后来的课程工作台设计想做面向老师的全周期系统，陆续加入了多班级、授课关系、布置记录与版本固定、课时安排、主题单元、课程目标追踪、单元讲评、本班调整版等能力。每一项单独看都有道理，合在一起后，老师面对的是“课程 → 任务 → 项目 → 布置记录 → 轮次”五层结构：

- 同一排阶段标签里，01–02 是共用内容，03–05 是“某个班某一次布置”，要靠下拉框切换；
- 一个页面同时出现本页要做的事、去别处补的东西和下一阶段，提示互相矛盾；
- 为研究、学期管理和多班服务的功能都挂在老师的主界面上。

首版因此收束为：**一节课一个工作区，闭环在这节课内完成；课程只是一层“免得重复填写的背景”；两节课之间只有一条连线。**

**收束准则**：以后加任何功能，先问它属于这节课五步中的哪一步，还是属于课程背景。都不是的，放入后续阶段，不进首版界面。

## 2 首版做什么、不做什么

### 2.1 做

| 部分 | 内容 |
|---|---|
| 课程背景 | 学科、年级、学生名单（一个班）、教材与课程资料；填一次，每节课自动带入 |
| 一节课的工作区 | 01 备课设计、02 出题改题、03 作业批改、04 学情分析、05 讲题答疑；讲评后再练（第 2 轮） |
| 进入下一课时 | 新建下一节课，带入本课已确认的学情，用于下一节备课 |
| 闭环内的规则 | 版本与确认、已参考、证据核对、没有作答只给易错点、修改上游后提醒更新、A/B 选择、导出文件 |

### 2.2 不做（首版界面不出现，数据层代码保留不删）

| 收掉的 | 原来服务于 |
|---|---|
| 多班级、授课关系、布置记录、版本固定、新版本可用 / 保持原版本、用于其他班、本班调整版 | 一份内容给多个班 |
| 课时安排（计划中、已上课、日期、过期提醒） | 学期进度 |
| 主题单元、按内容查看、跨课时的课程目标追踪、跨作业的单元讲评 | 单元与周期 |
| 任务与项目的区分、四种任务类型、其他工作区、单独项目 | 多入口、多容器 |
| 试用意愿问题 | 研究 |
| 研究记录、训练授权、数据集导出、旧项目整理 | 研究与运维（仍在“后台管理”，只对管理员） |

## 3 概念与用词

老师只需要理解四个概念：

| 概念 | 说明 |
|---|---|
| 课程 | 一门课的背景：学科、年级、名单、资料。不承担进度管理 |
| 一节课 | 工作单位，例如“对数函数｜第 2 课时”。五个阶段的成果都在这里 |
| 第 2 轮（再练） | 讲评后针对共性问题出的再练题，以及这些题的作答、批改和学情，仍属于这节课 |
| 下一节课 | 由“进入下一课时”建立，带着本课学情 |

**界面用词**：课程、一节课（课时）、教案、题目、评分标准、作答、批改、学情、共性问题、讲评稿、再练、需要更新、已参考。

**界面上不再出现**：任务、项目、工作区、产物、布置、布置记录、授课关系、问题模式（改称“共性问题”）。

## 4 页面结构

只有三个页面，外加管理员的后台管理。

### 4.1 首页

```
高一数学（3 班 · 42 人）                           [课程设置]

  对数函数｜第 3 课时    11月20日   继续：确认教案
  对数函数｜第 2 课时    11月18日   继续：汇总第 2 轮学情
  对数函数｜第 1 课时    11月15日   已讲评

  [ 新的一节课 ]
```

- 每节课一行，按最近修改排序；“继续：……”取自这节课当前要做的那一步，点击直接打开对应位置。
- 需要老师处理的事（待复核、需要更新）写在对应那节课的“继续”里，不另设“需要处理”区域。
- 第一次使用、还没有课程时，首页只显示建课程的表单。

**新的一节课**：填主题和课时（例如“对数函数 / 第 2 课时”），再选从哪里开始：

| 选项 | 进入 |
|---|---|
| 从备课开始 | 01 |
| 我有作业要批改 | 03（在 03 里导入题目） |
| 我想讲一道题 | 05（直接粘贴题目） |

三种选项建出来的都是同一种“一节课”，之后随时可以回到任何阶段补齐。

### 4.2 课程设置

学科、年级、班级名称、学生名单（每行一个代号）、教材与课程资料。只在第一次填写，之后很少打开。

### 4.3 一节课的工作区

```
我的教学 › 对数函数｜第 2 课时                 数学 · 高一（3）班
[01 备课设计 ✓] [02 出题改题 ✓] [03 作业批改 ✓] [04 学情分析 待办 ②] [05 讲题答疑]
```

- 五个阶段标签平铺，不分课前、课后。做完的打 ✓；闭环当前走到的那一步标“待办”，全页只有这一个“待办”。
- 有第 2 轮时，02–05 页面上方显示一个轮次切换“第 1 轮 / 第 2 轮（再练）”，默认最新一轮。只有存在第 2 轮时才出现。
- 没有单独的“文件”标签。导出放在对应阶段确认后的结果下面：01 导出教案，02 导出学生练习和答案与评分标准，05 导出讲评提纲；没有已确认内容时不显示。
- 需要更新的结果显示在它所属阶段的页面顶部（批改在 03，学情和共性问题在 04，讲评稿在 05），标签上的数字是这一阶段有几项。

## 5 五个阶段

| 阶段 | 产出（需老师确认） | 开始需要 | 缺了怎么办（就地补齐） | 完成后“接着做” |
|---|---|---|---|---|
| 01 备课设计 | 教学目标（含达成标准）、重点难点、课堂活动 | 主题、课时 | 无 | 按本课目标出题 |
| 02 出题改题 | 题目、答案、评分标准 | 无硬性前置 | 没有确认的教案时也能出题：系统先反推目标，标“未确认”；01 里有未确认的教案草稿时，提示先确认 | 准备批改 |
| 03 作业批改 | 逐题逐要点的批改，复核结果 | 已确认的题目和评分标准、名单、作答 | 没有题目：在 03 里直接导入试卷或手工录入，结果就是 02 的题目；名单为空：在 03 里直接粘贴 | 汇总学情 |
| 04 学情分析 | 得分统计、共性问题（每条有作答原文为证） | 已确认的批改 | 没有作答时只输出“可能的易错点”，不输出本班结论 | 准备针对性讲评 |
| 05 讲题答疑 | 讲评稿：讲解重点、关键步骤、典型错误、课堂追问 | 已确认的共性问题 | 没有学情时，直接粘贴一道题生成讲解 | 生成再练 / 进入下一课时 |

**02 的三种题目来源平级并列**：AI 出题、导入现成试卷、手工添加。导入试卷在 02 是因为它产出的是题目；在 03 发现缺题目时，03 页内嵌同一个导入入口，不把老师打发去 02。

**A/B 选择**只在 02 出题时偶尔出现（按现有的抽样规则），不进入其他阶段。

## 6 页面规则

### 6.1 一条规则管所有阶段的标题区

| 状态 | 标题区右侧 | 标题下方 |
|---|---|---|
| 本阶段已完成 | 绿色按钮“下一步：……” | 无 |
| 未完成，可以做 | 空。要做的事就在页面里 | 无 |
| 暂时做不了（缺前置条件） | 空 | 一条提示：原因，加上就地补齐的入口；确实只能去别的阶段时，按钮写“去 0N ……” |
| 正在等模型 | 灰字“……中” | 不变 |

闭环走到哪一步，只看标签上的“待办”，页面里不再重复说一遍。

### 6.2 缺什么就在当前页补

优先把补齐的入口放在当前页（03 导入题目、03 粘贴名单、05 粘贴题目）。补出来的东西归到它所属的阶段，并在那个阶段显示。

### 6.3 已参考

每次生成后显示这次实际读取了哪些内容，例如“已参考：本课目标、题目第 3 版、确认的评分标准”。沿用现有实现。

### 6.4 需要更新

已确认的题目、评分标准或教案做了**实质修改**后：

- 用旧版本得出的批改、学情、共性问题标“需要更新”；
- 在它所属阶段的页面顶部列出，直接给“重新批改 / 重新分析”和“保留原结果”，阶段标签上显示数量；“下一步”先指向闭环里最靠前的那一处；
- 旧结果保留，可追溯；新结果确认后才生效；
- 文字修改不触发提醒。

## 7 一致性与证据规则（沿用现有实现）

- 作答跟随这节课**最新确认**的题目和评分标准；不再在“布置”时固定版本。
- 批改只读本题的题目、评分标准和这份作答；学生以往的表现不影响本次给分。
- 能用工具核对的评分点以工具为准；模型判定必须逐字引用学生原文；没把握的转老师复核。
- 共性问题必须引用作答原文，服务器核对；证据不足时给出补查问题。
- 部分批改可以生成部分分析，标明覆盖人数，不作为全班结论。

## 8 再练与下一课时

**再练（第 2 轮）**：在 05 点“生成再练题”，针对选中的共性问题出题，进入 02 的第 2 轮；之后在 03 导入第 2 轮作答、批改，在 04 汇总，并对比两轮（只比较两轮都有作答的学生）。

**进入下一课时**：在 05（或本课已有确认的学情时）点“进入下一课时”，新建下一节课，课时号自动加一，可修改；本课已确认的共性问题、学情概述和讲评重点冻结成一份快照，显示在下一节课 01 的顶部，生成教案时用于安排回顾。这是两节课之间唯一的连线。

## 9 典型走法

**正常一节课**：新的一节课（从备课开始）→ 01 生成并确认教案 → 02 出题、核对、确认 → 03 导入作答、批改、处理复核 → 04 汇总、确认共性问题 → 05 生成并确认讲评稿 → 再练或进入下一课时。

**拿着现成作业来批改**：新的一节课（我有作业要批改）→ 03 页提示“还没有题目”，在本页导入试卷，核对确认 → 粘贴名单和作答 → 批改 → 04 → 05。没有教案也能走完；导入试卷反推的目标标“未确认”。

**讲一道题**：新的一节课（我想讲一道题）→ 05 粘贴题目和学生疑问 → 生成讲解草稿。没有作答时内容标为通用讲解。

## 10 与现有实现的对应

### 10.1 直接复用

| 能力 | 现有实现 |
|---|---|
| 一节课 | `projects`（每个课时一个），五阶段的产物和规则全部沿用 |
| 不挂布置的作答 | `scope.py` 中项目自己的作答：跟随最新确认版本，名单为项目名单，有轮次 |
| 修改后提醒更新 | `artifacts.mark_downstream` 与 `stale_marks`（不挂布置时按原规则传递） |
| 进入下一课时 | `next_lesson`：复制名单，冻结本课学情为 `carryover` |
| 反推目标、就地导入试卷 | `generate_questions` 的反推目标、`import_paper` |
| 已参考、证据核对、A/B、导出 | 现有实现不变 |

### 10.2 需要新做或调整

1. **课程背景变薄**：课程保存学科、年级、班级名称、名单和资料；新建一节课时自动带入。名单的存放有两种做法，实施时选一种：(a) 课程下保留唯一的一个班，界面不显示班级概念；(b) 名单存在课程上，新建课时复制到项目。倾向 (a)，改动小，以后恢复多班也方便。
2. **首页重做**：课时列表加“继续：……”，加“新的一节课”的三个选项，去掉开始工作四按钮、任务列表、班级卡片、按内容查看、需要处理、试用问题、其他工作区。
3. **工作区收窄**：去掉布置记录下拉框和“正在看：某班”一行；03 内嵌导入题目和名单；轮次切换只在有第 2 轮时出现；“文件与记录”取消，导出和需要更新分别回到各阶段（4.3），研究和试用卡片移出。
4. **02 去掉“布置给班级”**：题目确认后即可在 03 导入作答。
5. **“下一步”逻辑简化**：`steps.py` 中与布置、其他班级相关的分支在首版不再触发。
6. **用词替换**：按第 3 节统一界面文字。

### 10.3 已有数据

演示和冒烟数据里有两个班、带布置记录的课时。首版界面只显示不挂布置的作答；已有的布置数据仍可在后台查看，不做迁移。正式试用从新建的单班课程开始。

## 11 本轮会话中已有的未提交改动

2026-11-21 根据交互评估做过一批改动，与此前的其他未提交改动混在同一工作区，尚未提交。按本方案处理如下：

| 改动 | 处理 |
|---|---|
| 02 目标覆盖区分“反推的目标”和“01 未确认的教案草稿”；第 2 轮不把其他目标标红 | 保留 |
| 标题区统一规则、提示条按钮写明去哪一页 | 保留，按 6.1 调整为“优先就地补齐” |
| “需要更新”的用词、原因写法；两轮对比改为下拉选择 | 保留 |
| 开始工作四个入口各自的表单 | 由 4.1 的“新的一节课”取代 |
| 保持原版本、需要更新按班级和轮次区分、首页“需要处理”的保持按钮 | 多班功能，首版不显示；代码可保留 |
| 试用问题延后显示 | 随试用问题一起移出老师首页 |

## 12 首版验收

对应原始需求第（5）节的五项，限定为一个班、一节课：

| 验收项 | 怎样检查 | 通过标准 |
|---|---|---|
| ① 五类任务前后衔接 | 一节课内依次走完 01→05，再练一轮，再进入下一课时 | 每一步直接使用前面确认的内容；可以从 01、03、05 任一处开始；连续三节课不重复填写课程背景和名单 |
| ② 产物对老师有用 | 试点老师用自己的材料操作 | 教案和题目经修改后实际用于教学的比例不低于一半 |
| ③ 上下文准确、依据清楚 | 检查批改用的题目和评分标准版本、学情引用的作答、讲评针对的问题 | 能看到参考了什么；没有作答只给易错点；修改题目或评分标准后，受影响的批改和学情被标出 |
| ④ 反馈足够轻量 | 02 出现 A/B 时完成选择并继续 | 可以选择、跳过，选用的版本直接进入下一步 |
| ⑤ 研究记录可用 | 后台导出一节课的完整记录 | 能还原输入、候选、老师选择和最终修改 |

**界面验收**：每个阶段页面最多一条提示；全页只有一个“待办”；标题区没有与页面内按钮重复的按钮；界面上不出现第 3 节列出的禁用词。

## 13 实施状态（2026-11-21，`lesson-loop` 分支）

已按本文实现：

- **课程背景**：第一次打开时一张表填完课程名称、学科、年级、班级和名单（`POST /api/course-setup`）。课程下保留唯一一个班（10.2 第 1 条选 (a)）；课程设置里改名称、年级、名单和课程资料。
- **首页**：`GET /api/courses/{cid}/lessons` 列出每节课、五个阶段在任一轮是否完成、当前要做的一步；“新的一节课”（`POST /api/courses/{cid}/lessons`）分三种起点，分别打开 01、03、05。课时建立时复制班级名单；在课时里新加的学生同时加入班级，之后的课自动带上。
- **工作区**：不显示布置记录、“用于其他班”、“布置给班级”和 coursemaker 打包；有第 2 轮时 02–05 上方出现轮次切换；不再有“文件”标签：导出在 01、02、05 确认后的结果下面，需要更新的结果在所属阶段页面顶部，标签上显示数量（2026-11-21 补充）。
- **就地补齐**：03 缺题目时，提示条里直接粘贴试卷导入，导入的题目到 02 核对确认；同时给“去 02 出题”。
- **进入下一课时**：新课时属于同一课程和班级，带名单和本课已确认的学情。
- **新的一节课带上学情**（2026-11-21 补充）：课程里有已确认学情的课时时，新建表单多一个勾选项“带上「某课时」的学情”，默认不勾；勾选后与“进入下一课时”一样冻结一份快照带入。“最近”指最近有改动、且有已确认学情的那节课。课时之间不再自动读取“本班学情”。
- **用词**：界面上“问题模式”改为“共性问题”，“已参考”里“项目背景”改为“课时背景”。
- **后台管理**：旧项目整理移到这里。
