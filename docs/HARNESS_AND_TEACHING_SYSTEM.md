# Harness 与教学辅助系统：区别、联系与本项目的定位

本文说明两个常被混用的概念：教育模型的 **harness** 和**教学辅助系统**，以及本项目处在两者之间的什么位置。相关的研究证据见 [EDU_HARNESS_RESEARCH.md](EDU_HARNESS_RESEARCH.md)。

## 一句话区分

**harness 的服务对象是模型，教学辅助系统的服务对象是老师和学生。**

- **harness** 是包在模型外面的一层：决定模型在什么时候说什么，核对它说的和判的对不对，记录每一步，让人能追溯和纠正。它要解决的是“模型在教学中可靠吗”。
- **教学辅助系统**是面向教学场景的完整产品：账号与班级、练习与内容、布置与跟进、学情与复核、界面和运维。它要解决的是“学生学会了吗，老师的工作轻松了吗”。

在由大模型驱动的教学系统里，harness 是让模型可信的那一层；教学辅助系统包含它，但远不止它。

## 区别

| | Harness | 教学辅助系统 |
|---|---|---|
| 服务对象 | 模型：约束它的行为，核对它的输出 | 老师和学生：完成教学和学习 |
| 核心问题 | 模型会不会误判、泄露答案、没有依据就说学生学会了？出错了能不能拦住、追溯、纠正？ | 学生有没有学会？老师省了多少事？有没有人真的在用？ |
| 衡量标准 | 误判率、答案泄露率、策略回放是否一致、教学动作能否按设计执行 | 学习效果（前测/后测、迁移、保持）、老师节省的时间、使用和留存 |
| 主要内容 | 教学策略、判定证据、回复审核、轨迹与回放、模型调用的约束与预算 | 账号与班级、练习与内容、布置与跟进、学情与复核、界面、部署与运维 |
| 典型的失败 | 给出答案、误判、虚假的“已掌握” | 没人用、流程繁琐、内容不对路、老师不信任 |
| 能否单独存在 | 能，例如只做研究评测的 harness | 能，例如传统的智能辅导系统或学习管理平台，里面可以没有大模型 |

## 联系

### harness 是 AI 教学系统的可信度来源

老师敢把学生交给系统，是因为每个判定都有学生原文作为依据，能回放，能改判；学生不会被直接喂答案，是因为每条回复都要先审核。没有 harness，AI 教学系统就退化成“套了界面的聊天机器人”。高中数学的随机对照试验显示，学生使用不加约束的 GPT-4 时，练习成绩大幅提高，撤掉以后考试成绩却比没用过的学生低 17%；加了教学约束的版本基本消除了这种损害（Bastani 等，PNAS 2025）。

### 教学场景决定 harness 要做什么

harness 的许多设计，是被教学场景倒逼出来的：

- 老师要复核，所以 harness 必须保存判定依据和完整轨迹；
- 有班级和课程之分，所以证据要按班级隔离，跨会话的学习记录也要限定范围；
- 要区分“学会了”和“在帮助下做对了”，所以 harness 分别记录练习完成、辅助完成和独立检查，独立检查必须用新题；
- 老师改判以后，依赖这条证据的后续记录也要跟着失效。

### 两层互相影响

harness 的约束会直接表现为教学体验。v0.10 验收中的提示阶梯问题就是一个例子：9B 模型写的提示经常直接说出解法，被复核否决后换成通用兜底句，连续两次兜底就转给老师。从学生这边看，就是“要提示，系统却转给了老师”。修复也是两层一起改的：

- **harness 这一层**：写作和审核共用一份分级标准；加入程序检查（提示不得出现最终数值，不得用题目数字替学生列式）；配置了复核模型时，由它把关提示和讲解。
- **系统这一层**：准备按级别写好的提示模板，保证阶梯不中断；页面如实标注学生实际收到的是哪一种回复。

详细经过见[功能与测试记录第 5 节](FEATURES_AND_TESTS.md#5-提示阶梯与完整讲解的修复)。

## 一个视角：harness 把智能辅导系统的结构加回到大模型外面

传统的智能辅导系统（ITS）通常由四个部分组成，它们和 harness 几乎一一对应：

| ITS 的组成部分 | 作用 | 在本项目中对应的部分 |
|---|---|---|
| 领域模型 | 什么是对的 | 参考答案、评分要求与分项评分、代数等确定性工具、知识点库 |
| 教学模型 | 下一步怎么教 | 纯函数教学策略（`core/tasks.py`）、分级提示 |
| 学生模型 | 学生现在会什么 | 证据类型与学习记录（`core/memory.py`），没有掌握程度的估计，是目前最弱的一块 |
| 交互界面 | 和学生交流 | 学生和教师工作台，加上模型负责的自然语言理解与表达 |

大模型带来了传统 ITS 很难做到的事：理解任意学科、任意表述的作答，用自然语言写反馈，几乎不需要人工编写辅导内容。但如果直接让模型辅导，原来由人设计的结构也一起没有了：谁决定教法、谁保证判对、谁记录学生的状态。

**harness 做的，就是把这些结构重新加回到模型外面。** 因此可以这样理解：

> harness ＋ 界面 ＋ 内容 ＋ 教学流程 ＝ 由大模型驱动的智能辅导系统

这也给出了检查清单：一个教育 harness 是否完整，可以看它是否覆盖了领域模型、教学模型和学生模型这三块。本项目前两块比较扎实，学生模型还需要补（见[调研文档第 6 节第 2 项](EDU_HARNESS_RESEARCH.md#第-2-项显式的学生模型)）。

## 本项目的定位

本项目最初是一个 harness。v0.6 到 v0.9 的核心工作，都在判定可靠性、回复审核和策略回放上。之后逐步长出了教学系统的部分：班级、练习、批量出题、学习路径、学情和复核；v0.10 又加上了正式的网页工作台、逐路由的权限和新的存储层。

所以它现在**处在两者之间**：

| 层 | 现状 |
|---|---|
| harness | 比较扎实：证据绑定、纯函数策略、回复审核与复核、证据类型、策略回放、改判传播，都经过了自动化测试和真实模型验收 |
| 教学系统 | 核心流程可用，但缺少正式产品需要的部分：账号管理、内容建设、访问限流、运维，以及真实课堂的使用经验 |

接下来的投入方向取决于定位：

- **如果定位是“OmniEdu 的教学 harness”（研究导向）**：教学系统保持够用即可。重点投入评测（裁判独立、以学习效果为准）、学生模型，以及把交互数据变成训练数据、改进模型本身（例如用轨迹中“被否决的草稿 / 通过的重写稿”做偏好训练）。
- **如果定位是“教学辅助产品”**：主要补系统层，包括账号管理、内容建设、老师的日常工作流程、访问限流与运维、真实课堂试用。harness 已经不是主要瓶颈。

两个方向都需要的，是一次小规模的真实课堂试用。它同时检验两件事：harness 在真实学生面前是否可靠，系统对老师和学生是否真的有用。
